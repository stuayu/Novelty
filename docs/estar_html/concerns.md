# 実装上の懸念事項

## 結論

技術面では調査可能な実装入口がある。作品/目次はSSR HTML内`#__NUXT_DATA__`、本文は内部GraphQL。作品IDは数字のみの単一要素。本文は非ログインCookieだけで取得でき、CSRFは不要だった。

ただし、現時点で実装着手可とは結論しない。会員規約第10条3項がコンテンツの複製・送信・譲渡・貸与・翻訳・翻案その他の利用を明示禁止している。NoveltyのDrift/Hybridローカル保存と本文取得はこの条項に抵触する可能性が高い。オーナーによる規約方針決定が必要。

## ランキング・検索の調査結論（2026-08-26）

ランキングは実装可能な入口と結果構造を確認した。公開ランキングURL、5種別のリンク、SSRの`ModelNovel`、作品ID・タイトル・著者・あらすじ・ジャンル・タグ・話数・文字数・順位・スター関連フィールド、15件/ページ、`page=2`ページングを確認。`RankingTypeMaster`候補を定義できる。

検索もキーワード検索と結果構造を確認した。`keyword`、sort・状態・除外条件などのGETパラメータ、SSRの結果、30件/ページ、総件数、`page=2`ページングを確認。`NovelSearchQuery.word`を対応できる。

したがって、キーワード検索とランキングの基本実装は可能。ただし、ジャンル絞り込みの正式なクエリ名・値、ランキング全種別・全期間のURL組み合わせ、スター数の表示指標としての意味は未確認。これらを必須機能とする場合は追加調査が必要。

## 必須回答

- 使える取得手段: 公式APIの公開文書は未確認。内部API `POST /api/graphql` は実確認。SSR埋め込みJSONも実確認。HTML DOMは補助。
- 作品ID: 単一要素の数字文字列。
- 100話超: 100話超作品での実測は未確認。本文APIは15ページ単位。100話超の目次全件取得が現実的なリクエスト数かは未確認。
- ルビ: 本文の`|漢字《よみ》`を確認。`NovelContentElement`へ変換可能。ただし`packages/tategaki`の縦書き結合は未試験。
- CSRF/Cookie: 本文GraphQLはログイン不要。公開GETで発行される`guestinfo`と`requestor_id` Cookieが必要。CSRFは未要求で成功。ログイン後との差異は未確認。
